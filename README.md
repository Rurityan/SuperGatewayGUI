# SuperGateway GUI 2.0

支持中英文的 Windows MCP 网关管理工具，使用 Rust 与原生 Win32 控件。每个服务独立端口、独立启停；支持本地 MCP、远程 Streamable HTTP/SSE，输出 HTTP、SSE 或 WebSocket。

本项目是基于 [supergateway](https://github.com/supercorp-ai/supergateway) 的独立 GUI，不是上游官方产品。当前 Cargo 版本为 `2.0.0`。

## 运行便携版

解压 `SuperGatewayGUI-win-x64.zip`，双击目录中的 `SuperGatewayGUI.exe`，保留旁边的 `engine` 目录。面向 Windows 10/11 x64，不需要安装 .NET、Node、Python、WebView 或 VC 运行库。

第三方 MCP 的 Node.js、uv、Python 和包依赖可通过应用内管理界面下载，无需写入系统或用户 PATH。独立 exe 和远程 MCP 不需要这些环境。默认仍使用已有程序 / 完整命令；导入配置和启动服务不会自动安装。

## 界面语言

在“设置 → 界面语言 / Language”中选择“跟随系统 / System”“简体中文”或“English”，点击保存后立即切换，不重启 GUI 或网关。旧配置默认跟随 Windows 显示语言：中文显示语言使用简体中文，其余使用英文。

语言偏好以可选 `Language` 字段保存在当前配置目录的 `settings.dat` 中，重启后恢复；不进入服务配置导出。界面、常用提示、AI 向导和八章内嵌帮助支持中英文；英文界面会要求 AI 用英文填写说明。服务名称、命令、路径、参数、变量和密钥保持原样。MCP 原始日志、系统诊断和模型已有回复不自动翻译。使用说明另见 [English](README.en.md)。

## AI 辅助 MCP 安装向导

在“设置 → AI 安装向导”填写 `base_url`（例如 `https://api.example.com/v1`）、`api_key`、`model`，点击“保存 AI 设置”。本地兼容接口也可使用 HTTP 和空密钥；API 前缀后统一追加 `/chat/completions`，不自动改用其他协议。“测试连接”会发出一次可能计费的请求。密钥默认隐藏，随 settings.dat 由 Windows DPAPI 加密，不随服务配置导出。

从本地服务或依赖窗口点击“AI 安装向导”，输入公开 GitHub 仓库根地址，可选填写分支；也可直接粘贴 README。读取默认 / 指定分支时先固定到提交，再获取 README、根目录包描述和 README 链接的同仓库安装文档，最多 8 个文件 / 256 KiB。不克隆、不执行仓库内容；其他来源、私有仓库或抓取失败时请粘贴资料。API、仓库和包源读取使用“运行环境与依赖”中的代理设置，例如 `http://127.0.0.1:10808`。

点击“预览并生成方案”先检查实际发送内容；此时尚未请求 AI。点击预览窗口中的“确认发送”后才开始生成，成功后自动进入“2. 分析结果”。自动附加的环境摘要仅包含 Windows x64、已检测的托管版本、解释器类型和服务启动配置结构，不包含本机路径、变量值、密钥或其他服务；你主动粘贴的文档和补充要求会发给所配置的 API，请自行检查。生成过程可取消，AI 请求总超时 120 秒，不自动重试。

结果包含参数说明、所需变量、运行条件、一次性 setup 步骤和不确定项。GUI 校验结构，并向所选 npm / Python 包源核实包和版本；“已确认”只表示包源存在，**不表示已安装或保证可用**。源不可访问或无法解析时标记未验证，包不存在时阻止采用。可返回资料页补充要求后重新生成。

在审核页逐项勾选启动方式、包配置、参数与环境变量；选中变量行后点击“填写选中的环境变量”，填写实际值，占位密钥不能采用。这些本机填写的值不会发送给 AI。“填入勾选项到草稿”不保存、不安装、不启动。之后核对主表单并保存，手动安装运行环境及包，再测试连接。已有完整命令保留且继续优先，采用托管入口时需手动清空它。

setup 仅在分析结果及“一次性步骤”中展示，可选择复制；安装完成后，将其参数逐项填入现有“一次性命令 / 安装向导”并确认运行，不能放进常驻参数。AI 无命令执行能力；不支持的构建方式只给说明，不转换成自动 shell 脚本。关闭向导即丢弃资料和生成历史，已采用的服务字段照常保存和导出。真实 API 兼容性取决于供应商；当前验证使用本地模拟接口，不调用付费模型。

## 应用内运行环境与依赖

存放路径可在“设置 → 配置与依赖路径”分别修改。用户配置目录保存 settings.dat、证书和备份；依赖目录保存共享运行环境、服务包和缓存。点击“保存并重启”会复制配置和证书到空的新配置目录，保留原目录；**依赖不迁移、不删除、不自动安装**，适合先选好目录再安装环境。配置目录选择保存于默认目录的 locations.json；依赖路径保存于当前配置目录的 storage.json，不写环境变量。`--data-dir` 优先于界面记住的配置目录，显式指定该参数的快捷方式需自行更新。已启用管理员登录启动时，变更路径也需管理员权限以更新计划任务。

1. 添加本地服务，启动方式选择“应用管理的 npm / Python 包”。程序路径可以留空，完整启动命令留空以使用包入口。
2. 点击“配置包与安装依赖”，选择 npm / Python，填写包名、可选版本、入口和参数，勾选“此服务使用应用管理的运行环境”。点击“保存并关闭”，再保存主界面的服务；未安装时显示“待安装”。保存不下载、不执行命令，也不要求先运行 setup。
3. 在依赖窗口选择环境并点击安装：npm 需要 Node.js；Python 需要 uv 和 Python。然后点击“安装 / 更新服务依赖”并确认；安装第三方包可能执行其代码。完成后版本固定，保存依赖和服务；运行中的服务通过“应用并重启”切换。

“从原始命令识别”可预览简单 npx / uvx 配置，复杂 shell 命令需要手动填写。便携包不预装环境；没有依赖时启动或运行向导会提示前往安装，不自动下载或回退到系统环境。使用已有程序方式时，填写程序名或完整命令即可保存，程序是否可运行在启动时检查。

示例：npm 包 `@modelcontextprotocol/server-filesystem`，入口 `mcp-server-filesystem`，点击“编辑启动参数”，每个独立输入框填写一项，例如 `D:\我的资料`；Python 包 `mcp-server-fetch`，入口 `mcp-server-fetch`。版本留空时在安装时解析当前版本并保存实际版本；再次更新需填写新的确切版本，或清空版本后明确点击安装。

**一次性安装向导**：安装好服务包后，在“配置包与安装依赖 → 一次性命令 / 安装向导”填写临时参数（每项一个独立输入框，横线分隔），预览实际入口后确认，打开可交互终端执行。它使用当前已安装的固定版本，不再次通过 uvx / npx 临时下载；不会修改服务启动参数。终端可按提示输入，完成后显示退出码并等待 Enter；关闭终端会清理该终端管理的进程树。终端独立于 GUI，完成后请手动关闭；GUI 当前运行期间会记录其依赖引用，避免删除或清缓存。

例如 `uvx mcp-for-blender setup`：先选择应用管理，在服务依赖中选择 Python 包，包名填写 `mcp-for-blender`，入口与正常启动参数留空，勾选应用管理并保存；无需填写程序路径。随后手动安装 uv、Python 和包；然后点击“一次性命令”，参数填 `setup`，确认后完成向导。正常 MCP 服务的启动参数留空，**不要填 setup**。该上游向导可能修改其他客户端配置、安装并启用 Blender 插件，具体由你在终端选择；如只需要插件可用临时参数 `install-addon`。本应用不替第三方向导更改行为，它生成的客户端配置仍可能引用 uvx 并独立管理自己的包缓存；若希望客户端通过本 GUI 网关访问，请使用本应用的客户端配置导出。

一次性命令允许程序按当前代理 / 包源设置联网，例如下载插件，仅给其子进程注入 PATH、缓存和网络变量；托管 Python 不自动安装系统解释器。程序可能修改其目标应用文件，执行前请查看预览。此入口只接受已安装的包及参数，不执行粘贴的任意 shell 表达式；未安装时提示先安装。

固定 Windows x64 清单：Node.js **24.21.0 LTS**、uv **0.13.0**、CPython **3.13.16 / 20261009** 便携发行。官方 HTTPS 下载经内嵌 SHA256 验证后解压，不调用下载脚本。管理界面支持 HTTP 代理（如 `http://127.0.0.1:10808`）、单独代理凭据、npm 包源和 Python 包源；默认官方源直连，凭据由 DPAPI 加密保存。

默认依赖目录为数据目录下的 `dependencies`，也可单独选择位置。其中 `runtimes` 保存共享运行环境，`services/<服务 ID>/<安装 ID>` 保存独立包目录，`cache` 为共享缓存。npm 使用 `package-lock.json`，Python 使用带哈希的 `requirements.lock` 及独立虚拟环境。每次安装使用新目录，失败或取消不替换旧版本；旧目录保留，可在服务停止后删除其全部依赖。被服务配置或运行中服务引用的运行环境不能删除；清理共享缓存前需停止服务。

只给 MCP 和安装任务设置子进程 PATH、缓存及相关变量，不修改 GUI 全局 PATH、用户或系统环境变量。默认服务仍沿用原有命令查找；切换托管模式保留原始命令，切回即可恢复。托管结构化启动直接使用已安装入口，不临时运行 npx / uvx 下载。完整启动命令仍优先，托管模式只提供选定工具及离线缓存，不能保证任意 shell 表达式可复现；PATH、缓存等保留变量不能在服务环境列表中覆盖。

支持 `--data-dir`。移动便携包或数据目录后重新导出配置；Python 虚拟环境包含原始绝对路径，移动数据目录后需重新安装 Python 服务依赖。离线启动不下载依赖，但 MCP 程序自身仍可能联网。

网络专项验收：`./scripts/test-dependencies.ps1 -Proxy 'http://127.0.0.1:10808'`，仅使用隔离的测试目录，包含实际包安装、空 PATH 离线启动及用户/系统环境变量对照；不属于常规离线测试的自动下载行为。

## 配置服务

### 每服务环境与附加程序目录

在本地服务的“环境 / 请求头 / 密钥”页设置“继承系统环境变量”，默认开启。这里的系统环境是 GUI 启动时继承的快照；外部修改后需重启 GUI。关闭时保留必要 Windows 变量（含用户配置、临时目录及系统程序路径），其余仅来自服务注入和托管环境。变量名称不区分大小写，服务注入覆盖继承值；空值保持为空。设置不改变用户或系统环境，也不影响其他服务。

“附加程序目录”使用目录选择器添加，可选中删除，按列表顺序查找。托管 PATH 顺序为：服务虚拟环境 → 托管工具 → 附加目录 → Windows 目录 → 继承的 PATH；关闭继承时省略最后一项。原有程序模式可显式填写 PATH，附加目录放在该 PATH 前面。托管模式禁止直接覆盖 PATH、缓存和解释器等保留变量。缺少托管环境仍报错，不会通过系统 PATH 回退；安装任务使用独立的受控环境。

例如 Blender 位于 `D:\图形工具\Blender 4.5\blender.exe`，添加 `D:\图形工具\Blender 4.5` 即可让已安装包的 setup 通过 PATH 找到它；无需写 Windows 环境变量。先打开 Blender 一次并退出，再手动执行一次性 setup。这里只验证受控模拟 Blender，没有自动执行真实 Blender 安装。

“预览服务环境”显示变量来源、最终 PATH 和启动方式，变量值隐藏；尚未安装依赖时也可预览，不下载或创建依赖目录。正常 MCP、完整命令和一次性向导采用相同继承规则；向导按其用途允许联网。保存运行中服务的修改后，通过“应用并重启”生效。包依赖隔离和环境继承是不同设置；继承开关不是安全沙箱。


### 批量导出与导入完整服务配置

服务列表上方“导出配置”可勾选服务，支持全选 / 全不选，保存为 JSON。包括基础设置、高级设置、环境继承、附加 PATH、环境变量、请求头、全部密钥、托管包规格及客户端超时等已保存参数；遇到未保存修改时先选择保存、放弃或取消。导出使用独立的 `SuperGatewayGUI` Version 1 格式，方便备份和跨目录迁移，客户端连接配置仍在“客户端配置 / 导出”页复制。

“导入文件”或“粘贴导入”识别完整 GUI 格式及原有 `mcpServers` JSON / JSONC。预览中勾选需要的服务后一次保存；错误项不可导入，重名自动加后缀，冲突端口重新分配，始终新增服务而不覆盖已有服务。取消不会导入；导入不启动 MCP、不下载或安装依赖。

**导出文件中的环境变量、认证头和密钥为明文**，含值时会再次确认，请妥善保管，勿提交 GitHub。预览隐藏参数值；本机保存仍使用 DPAPI。文件不包含已安装依赖、TLS 私钥、运行状态或应用全局路径 / 网络设置。导入后托管依赖需要在本机安装，HTTPS 使用本机 CA，客户端需重新信任；工作目录等本机路径必须有效，错误原因会在预览中显示。保留启用及自动启动偏好，但本次导入不会启动服务。

主窗口顶部“帮助”可打开随界面语言切换的中英文离线文档，按章节查看参数含义、本地命令、远程认证、监听地址、高级设置、导入示例、Codex TOML 和故障处理。帮助窗口可调整大小，正文可滚动、选择和复制，无需联网或额外文档文件。

1. 点击“添加”，填写名称，选择本地 MCP 程序、远程 Streamable HTTP 或远程 SSE。已有 `mcpServers` 配置可以直接导入。
2. 本地填写程序名或浏览选择文件。点击“编辑参数”逐项填写，每个参数一个独立输入框，行间用横线分隔，可添加、删除、上移、下移；每项首尾空格、换行、制表符自动清理，内部空格和引号保留；粘贴也会清理，确认时提示调整项数。不要额外加引号，空输入框或纯空白项表示一个空参数，无参数时删除所有行。主表单只显示参数摘要，确认编辑后再保存服务配置。工作目录可浏览选择，留空时使用便携程序目录。也可粘贴“完整启动命令”，填写后忽略上面的程序和参数。应用启动时按 `pwsh 7 → Windows PowerShell → cmd.exe` 检测一次，固定本次运行的解释器；界面显示已选解释器，安装或改变环境后需重新启动 GUI。PowerShell 使用无配置文件、非交互模式，并设置 UTF-8 输入输出。

完整命令按所选解释器的语法执行。PowerShell 中含空格的程序路径通常写作 `& "D:\我的工具\server.exe" "参数"`；直接以引号包住的程序路径开头也会自动补上 `&`。以 `npx` / `npm` 开头时使用对应 `.cmd` 启动器，避免受 `.ps1` 执行策略影响。设置环境变量用 `$env:NAME='value'`，Windows PowerShell 不支持 PowerShell 7 的 `&&` 语法。CMD 的 `set`、`call` 等命令需改写为 PowerShell 语法。仅当高优先级解释器未安装时选择下一种，命令执行失败不会换解释器重试。普通“程序 + 参数”方式不受此优先级影响，`npx.cmd` / `.bat` 仍使用适合批处理的启动方式。
3. 远程填写 URL 和 Bearer Token。在“环境 / 请求头 / 密钥”页通过“添加、编辑、删除”管理键值。环境变量默认显示值；编辑框“隐藏内容”按每项保存，编辑框保存后再保存服务配置。切换服务、重开 GUI 或完整配置导入导出保留隐藏状态，列表总开关取消隐藏也不会显示单项隐藏值。只有明确编辑该项并取消“隐藏内容”才可显示；取消编辑不改变状态。列表“隐藏环境变量值”为临时额外隐藏。隐藏不改变实际变量、导出明文和日志脱敏。请求头和密钥仍默认隐藏，可勾选“显示内容”。本地服务的请求头列表用于网关响应头。
4. 默认输出 Streamable HTTP，监听地址默认 `0.0.0.0`（所有网卡）。下拉框提供 `127.0.0.1`（仅本机）和检测到的本机 IPv4 地址，显示对应网卡名称；网卡变化后点击“刷新 IP”。新服务从 8000 起选择可用端口，也可手动修改。局域网访问请按实际需要配置访问密钥和防火墙。旧配置保留原来的监听范围。
5. “高级设置”显示连接路径、网关访问密钥、CORS、会话设置和日志级别。SSE 显示消息路径；有状态会话及超时仅适用于 HTTP。表单可滚动，支持系统 DPI、窗口缩放和 Tab 键导航。
6. 保存后点击“启动”，再“测试连接”。测试执行 MCP 初始化及工具分页查询，展示工具名称和说明，不执行工具。

下拉框不通过滚轮切换选项：收起时滚轮用于滚动配置页面，展开时忽略滚轮。仍可用鼠标点击或键盘选择，避免滚动页面时误改来源、协议、监听地址及包类型。

“网关运行”表示监听成功；“MCP 验证成功”才表示本次初始化和工具查询通过。本地 MCP 通常在客户端连接时才启动。失败原因显示在状态区和日志中，不会无限自动重启。

点击“保存配置”后弹窗确认保存成功；校验或写入失败时显示失败原因。成功弹窗也会提示待应用修改或尚未安装的依赖。运行中修改配置并保存后显示“待应用”，用“应用并重启”生效。该操作只重启当前服务。切换服务或新建时，未保存修改会提示保存、放弃或取消。“全部启动”使用已保存配置，并跳过未启用服务。

## 局域网 HTTPS / WSS

在服务“高级设置”勾选“启用 HTTPS / WSS”，保存并启动（运行中使用“应用并重启”）。端口保持原设置，地址变为 `https://IP:端口/路径` 或 `wss://IP:端口/路径`。后端网关仅监听 `127.0.0.1` 的独立内部端口，不同时开放明文局域网入口。

所有服务共用一张证书，包含回环和已连接网卡 IPv4，默认有效期约 20 年；本地 CA 约 30 年。无需公网、OpenSSL 或额外 Caddy 进程。首次启动自动生成，之后沿用；启动时及运行中每分钟检查，剩余不足 30 天或网卡 IP 变化时补签并热更新，新连接使用新证书，现有 MCP 会话与进程保持运行。证书失效/损坏时显示失败，不回退明文。支持 HTTP/1.1、SSE、WebSocket，目前没有 HTTP/2/HTTP/3。

“设置”提供生成/检查、导出公开 CA、信任本机当前用户 CA、取消信任和重建 CA。信任前确认；其他客户端设备仍需导入公开 CA。Windows 导出 `.cer`，导入当前用户“受信任的根证书颁发机构”；Node/独立证书库导出 `.pem`，设置 `NODE_EXTRA_CA_CERTS` 指向它。不要忽略证书错误。公开 CA 可以分发，私钥不可分发。

Codex HTTP 导出使用 HTTPS URL，客户端需信任 CA；SSE 客户端直接通过网络连接，按客户端要求导入公开 CA。HTTPS 服务不能直接复制上游网关 JSON，因为它无法表达 GUI 的 TLS 入口。

证书保存在数据目录的 `tls` 子目录。私钥以 DPAPI 加密在 `ca.dat`、`server.dat`，目录权限限制为当前用户与 SYSTEM；公开 `root.crt`、`server.crt` 不含私钥。损坏数据不会自动覆盖 CA 身份。重建前停止 HTTPS 服务，旧目录保留备份，旧 CA 取消本机信任，各客户端需重新导入新 CA。CA 接近到期时必须更换并重新信任；不会静默替换根身份。管理员启动请使用同一 Windows 用户，保持 DPAPI 可读。

长有效期用于此私有 CA，部分客户端可能有额外期限限制，需以客户端验证结果为准。HTTPS 保护传输，访问密钥仍负责认证。每服务最多 64 个 TLS 连接，握手限时 10 秒；所有服务共享一个 TLS 工作线程，没有额外代理进程。

这里的 HTTPS 保护客户端到 GUI 网关的链路。远程 MCP 来源如果仍填写 `http://`，网关到该上游的链路仍为明文，应使用上游支持的 `https://` 地址。

## 导入、连接与导出

客户端连接参数集中在第四页“客户端配置 / 导出”，只生成连接 GUI 网关的配置，不影响网关和 MCP 服务。启动超时和工具超时单位为秒，留空使用目标客户端默认值；这些字段仅导出到 Codex TOML，通用 JSON 不写入专属超时字段。

不提供独立 stdio 或 SSE 转 stdio 输出，网关仅接受本地 MCP 的 stdio 输入并提供 HTTP / SSE / WebSocket 网络输出。HTTP 客户端发送网络请求，不会因此创建客户端侧 MCP 子进程，连接配置不导出环境变量。MCP 程序所需变量请在服务“环境 / 请求头 / 密钥”页设置，由 GUI 注入；客户端页不会覆盖这些变量。

旧文件中的 Client.Environment / Client.Stdio 字段为兼容保留，但不用于网络导出或服务运行。仅修改客户端超时不会将运行中的网关标记为待应用；修改已复制的配置需要重新导出。

“导入文件”支持 JSON/JSONC，“粘贴导入”读取剪贴板。导入预览显示识别结果、无效条目、重名调整和端口调整；确认后仅保存配置，不执行导入的命令。不支持的字段会显示错误，避免静默丢失配置。

“复制连接地址”供支持相应网络协议的 MCP 客户端使用。有访问密钥时客户端发送 `Authorization: Bearer <密钥>` 或 `X-API-Key: <密钥>`。地址使用 IP，不使用主机名：选择具体网卡时使用该 IP，监听所有网卡时优先使用带网关的已连接网卡 IPv4；没有可用网卡时回退 `127.0.0.1`。多网卡环境可通过监听地址下拉框指定网卡。`0.0.0.0` 仅是监听地址，不作为客户端连接目标。

“复制网关配置”移至高级设置，只生成上游引擎 JSON，不包含客户端参数。关闭环境继承时由 GUI 启动服务，保持服务环境限制。

“复制 Codex TOML”可粘贴到 Codex 的 config.toml，只支持 Streamable HTTP 网络连接；SSE / WebSocket 请切换输出协议并保存，运行中应用重启。地址与密钥使用已保存或当前实际运行的网关配置，客户端超时使用此页当前值，建议保存以便恢复。生成的稳定服务表名再次导出时应替换，避免重复 TOML 表。

“复制客户端 JSON”生成 mcpServers 网络配置：HTTP 使用 type: http，SSE 使用 type: sse，均包含 url 及可选 headers。具体字段支持取决于客户端；JSON 不含 Codex 超时字段，导出时明确提示。

网络导出不启动进程、不创建启动快照、不下载依赖。需要 GUI 中对应网关正在运行；认证只复制网关访问密钥，不复制上游 Bearer Token 或服务环境变量。HTTPS 客户端需信任公开 CA。格式依据 [OpenAI 官方 MCP 文档](https://developers.openai.com/codex/mcp/) 核对。

## 托盘、启动与配置兼容

关闭窗口会收起到托盘，服务继续运行。双击托盘图标恢复，右键可停止全部或彻底退出；主窗口也有“退出”按钮。有 MCP 网关服务运行时，彻底退出会询问是否关闭服务并退出，默认选择“否”；拒绝会保留 GUI 和服务，确认“是”后先关闭网关 stdin，超过 8 秒后清理该服务的进程树。没有运行服务时直接退出。Job Object 会在应用异常终止时清理所管理的网关和子进程。

登录启动默认收起到托盘。找不到图标时，再次双击相同配置目录的 EXE 会唤醒已有窗口，不创建第二实例或重新启动服务；重复的 `--background` 启动不会主动弹窗。资源管理器重启后会重新添加托盘图标；添加失败时显示窗口，避免隐藏后无法访问。普通权限打开同一 Windows 用户的管理员实例也可发送窗口恢复请求。

管理员计划任务须使用“仅当用户登录时运行”（程序生成的是 `InteractiveToken`）。手动改成“不管用户是否登录都运行”会进入非交互桌面，无法显示 GUI；请改回交互式登录任务。旧版正在运行时需先从任务管理器或任务计划程序结束对应 GUI 实例，再使用新版，避免旧实例继续拦截启动。

登录启动默认关闭，可在设置中开启。每个服务另有“应用启动时自动运行”开关。移动目录后应重新关闭并开启登录启动，以更新注册表中的程序路径。

设置中的“以管理员身份重启”会请求 Windows UAC 授权；取消授权时当前程序继续运行，同意后先停止网关并退出，再以管理员身份打开相同配置目录。未保存的服务修改会先提示处理。仅自动运行勾选的服务会在重启后恢复。

“开机时以管理员身份启动（登录后）”仅在管理员权限下可变更，普通权限时禁用。它使用当前用户、最高权限、无需密码的交互式登录计划任务，登录后启动到托盘，与普通登录启动互斥。启用和关闭都需要管理员权限；请使用同一 Windows 账户提权，以保持 DPAPI 配置可读。移动目录后在管理员模式重新保存启动设置，更新任务路径。这是用户登录启动，不是系统启动前运行的 Windows 服务。

默认配置位置为 `%LOCALAPPDATA%\SuperGatewayGUI\settings.dat`，采用当前 Windows 用户的 DPAPI 加密。可直接读取旧版 PascalCase JSON 加密配置，首次覆盖前保留 `settings.dat.pre-rust.bak`。读取失败会显示错误且不覆盖原文件。备份仍绑定原 Windows 账户，不是跨机器通用的配置导出。

支持 `--background` 启动到托盘，以及 `--data-dir "D:\我的配置"` 指定独立配置目录。旧 .NET 源码和便携包归档于 `legacy/dotnet`，不参与新版本构建。使用新包时请整体解压，避免混入旧版运行时文件。

底部“日志筛选”可选择全部服务或指定 MCP 服务，实时显示对应记录。切换筛选保留历史，服务改名后仍按服务 ID 筛选；删除当前筛选服务后回到全部。“清空当前日志”只清除当前筛选范围，全部服务模式则清空全部记录。

日志共用最多 1000 条或 128 KiB 的缓冲区，较早记录按顺序淘汰，单行截断，后台日志队列也限制容量。已知密钥、环境变量、请求头值及 URL 查询参数会脱敏。完整启动命令和普通参数不被当作密钥编辑器，请优先将秘密放入环境变量或认证字段。

## 从源码构建

开发机安装 Rust MSVC x64 工具链与 Visual Studio C++ Build Tools/Windows SDK。Cargo.lock 固定依赖，Release 使用静态 CRT、体积优化、LTO 和符号剥离。

应用图标由生图工具生成，内置于 EXE，并用于窗口、配置对话框、任务栏和托盘。源码 `assets` 目录保留原始图片、1024px 透明母版、九尺寸 ICO、浅色/深色预览及生成提示词。可选运行 `scripts/build-icon.ps1` 从原图重建图标；这是开发用 PowerShell/System.Drawing 工具，应用运行不需要它。Cargo 构建通过 `embed-resource` 调用 Windows SDK 的资源编译器嵌入 ICO，无新增运行时依赖。

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
# 首次构建需先准备固定版本网关；需要 Git、Node 24、npm 和 Windows SDK。
./scripts/build-engine.ps1
cargo build --release --locked
./scripts/test.ps1
./scripts/package.ps1
```

`engine` 文件齐全且校验通过时使用缓存；重建引擎使用 `scripts/build-engine.ps1 -Rebuild`，开发机额外需要 Git、Node 24 与 npm。用户机器不运行 npx supergateway。引擎固定上游提交，SHA256 在 `engine/manifest.json`，每次启动前验证。

可选 `scripts/test-legacy-compat.ps1` 使用 .NET SDK 调用归档的旧 SettingsStore 生成兼容性样本；它不是 Rust 产品或打包依赖。`scripts/measure.ps1` 使用相同 Rust MCP 测试程序对比旧版与新版，输出原始采样 JSON。验证结果、占用和未完成项目见 `VALIDATION.md`。

完整步骤和使用已发布网关的构建方式见 [DEVELOPMENT.md](DEVELOPMENT.md)。源码仓库不包含生成的引擎 EXE、构建缓存、个人配置或下载的运行环境；便携包通过 GitHub Releases 附件分发。

首版不包含 MCP 聚合、自动安装依赖、Windows 服务模式、自动更新或工具调用调试。
